# RSS Can v0.4.0

## 中文

这是从 v0.3.12 升级的次版本，包含 JavaScript 运行时与服务生命周期变更，不只是依赖补丁。

- JavaScript 从内嵌 v8go 迁移到常驻 Deno 2.9.8；默认 1 个 worker，可通过 `RSS_JS_WORKERS` 配置 1–16 个。请求使用隔离上下文，超时后恢复 worker。
- Linux/macOS 的 AMD64/ARM64 四种归档均附带固定摘要校验的官方 Deno、示例规则、许可证和双语升级指南。完整解压，保留同目录 `rssc` 和可执行的 `deno`，启动无需联网下载。Linux 运行时需要 glibc；Alpine 等 musl 环境使用 Debian 容器。
- Docker Hub 提供内置 Deno 的 `linux/amd64`、`linux/arm64` 镜像，固定标签 `soulteary/rss-can:v0.4.0`。
- 服务迁移到 Fiber 和 chromedp，完善启动/关闭、请求取消、浏览器隔离、队列与内存上限、就绪检查和监控指标。
- 固定规则快照，限制抓取与详情并发；保留订阅顺序、分页预算、日期/分类/字段语义与最终 URL 来源。
- Cookie/代理应用于 SSR、分页、详情及隔离浏览器；详情 hook 失败返回 502，整体超时返回 504，不再返回缺项订阅。
- 管理入口保持本机限制与 token 认证；Inspector 仍限制公网 HTTP(S) 目标。
- 更新 cache-kit v2.1.1、redis-kit v1.8.1 及 DOM、选择器、Markdown、Feed 依赖，保留第三方许可证。

### 升级与回退

备份规则和部署配置，确认 `RSS_CAN_DENO` 没有指向旧路径；查找顺序为显式路径、`rssc` 同目录、PATH。配置错误不会静默回退。保留 Redis 与 Chrome 配置，CSR/混合规则仍需要独立 Chrome。检查 `/_/ready/` 和实际 SSR、CSR、混合订阅，单独验证登录、代理、分页及详情 hook。

无需迁移持久化配置格式。回退时先停服务，再恢复原 v0.3.12 归档/镜像、配置及已验证规则；不要混用不同归档的文件。新功能配置不适用于旧版。详细步骤及容量参数见 [升级指南](../upgrading.md)。

```sh
docker pull soulteary/rss-can:v0.4.0
docker run --rm -p 8080:8080 -e RSS_REDIS=false soulteary/rss-can:v0.4.0
```

## English

This minor release includes all changes since v0.3.12, including a runtime migration and application lifecycle changes.

- Replace embedded v8go with persistent Deno 2.9.8 workers (default 1, configurable 1–16), isolated request contexts and timeout recovery.
- Bundle checksum-pinned official Deno in all four Linux/macOS AMD64/ARM64 archives, alongside rules, licenses and the bilingual upgrade guide. Extract the complete archive and retain executable sibling `deno`; startup needs no runtime download. Linux requires glibc; use the Debian container on musl/Alpine.
- Publish verified Docker images with Deno for both Linux architectures under `soulteary/rss-can:v0.4.0`.
- Adopt Fiber/chromedp; bound queues, browser/fetch/detail concurrency and memory; own startup/shutdown and expose readiness/telemetry.
- Preserve immutable rule snapshots, item order, pagination budgets, field/date/category semantics and final URL provenance.
- Apply cookies/proxies across SSR, details and browser contexts. Failed configured detail hooks reject the whole feed (502); overall deadlines remain 504.
- Retain management authentication and public-target Inspector restrictions. Refresh kit and optimized parser/Markdown/feed dependencies with license notices.

Back up rules/configuration and remove stale `RSS_CAN_DENO` overrides. Runtime lookup is explicit override, sibling executable, then PATH; invalid overrides fail. Redis and Chrome remain separate dependencies. Verify readiness plus your SSR/CSR/mixed, authenticated, proxied and paginated feeds. No persistent configuration migration is required. To roll back, stop the new service and restore the original v0.3.12 archive/image and compatible rules/settings; do not mix archive files. See the [upgrade guide](../upgrading.md) for limits and rollback details.
