# RSS Can v0.5.0

Release date: 2026-11-04

## 中文

v0.5.0 新增可选的 Stargate 团队模式、来源向导和私有订阅凭据，同时改进默认缓存、
订阅内容安全与部署边界。独立模式继续支持管理员维护的 JavaScript 规则；升级不会
自动启用团队鉴权。运行时仍为 Deno 2.9.8，无需再次迁移 JavaScript 引擎。

### 新功能与修复

- **团队权限**：使用 Stargate 验证身份、Warden 检查账号状态，为每个来源设置所有者和
  读取权限。阅读器使用可独立撤销的只读凭据；每次私有读取都重新鉴权，包括缓存命中和
  `304`。已禁用账号不会因再次登录而被自动启用。
- **来源向导**：无需编写 JavaScript 即可预览、保存公网 SSR 来源，编辑时校验版本，
  支持恢复、删除、手动刷新和阅读器凭据管理。限制选择器复杂度和页面预算，错误不会
  静默变成缺项订阅。`rssc doctor` 提供不修改权限库的启动诊断。
- **抓取边界**：团队模式强制公网 SSR，校验目标、DNS 和重定向，拒绝借缓存绕过策略。
  每次生成共用 64 次 HTTP 请求和 64 MiB 上游响应预算。管理员维护的内网、浏览器或
  Cookie/代理规则继续放在独立可信部署中。
- **快照与公平调度**：保存完整成功订阅，默认保鲜 30 秒，刷新时可额外返回最多 3600 秒
  的旧内容；支持 ETag/Last-Modified 与按所有者限制工作量。手动刷新绕过并更新页面缓存，
  较早的并发抓取不会覆盖更新后的内容；来源版本隔离，panic 后释放准备阶段配额。
- **输出安全**：所有规则输出的 HTML 均按允许列表清理；移除脚本、CSS、主动嵌入和自动
  加载资源，图片变为替代文本。JSON 摘要为纯文本，保留行内文本的自然连接，在块级内容之间保留分隔。
- **部署安全**：管理修改要求 POST 和显式操作头，日志隐藏敏感路径/查询内容，镜像以
  UID/GID 65532 运行，Deno worker 使用私有临时缓存。Stargate 示例只公开网关，隔离
  管理入口并生成私密配置，支持静态检查与实际 Nginx 验证。

### 升级前必读

1. 备份规则、部署配置及已有团队权限库。运行新版 `rssc doctor`，检查挂载权限和就绪接口。
2. 快照默认启用；需要关闭输出快照时设置 `RSS_SNAPSHOT_TTL=0`，禁止旧快照响应时设置
   `RSS_SNAPSHOT_MAX_STALE=0`。规则的 `DisableCache` 仍禁用缓存。
3. 检查依赖图片、自定义 CSS 或嵌入内容的订阅，它们的输出会变化，且没有单规则清理绕过。
4. 更新 `/config/*` 调用为 POST，并携带 `X-RSS-Admin-Action: 1`；保留认证要求，不能为
   所有登录用户注入管理员 token。
5. 团队模式需要独立配置身份、可信代理和来源权限；历史 v0.4.0 会忽略这些配置，不能
   作为团队模式的回退目标。权限库只能由一个进程写入，恢复备份后须重新核对撤销状态。

完整步骤见[升级指南](https://github.com/soulteary/rss-can/blob/v0.5.0/docs/upgrading.md#upgrade-v050)、[团队访问](https://github.com/soulteary/rss-can/blob/v0.5.0/docs/stargate-access.md)、
[快照](https://github.com/soulteary/rss-can/blob/v0.5.0/docs/feed-snapshots.md)和[内容安全](https://github.com/soulteary/rss-can/blob/v0.5.0/docs/feed-content-safety.md)。

## English

v0.5.0 adds optional Stargate team access, a source wizard and private reader
credentials, together with changes to default caching, feed HTML and deployment
boundaries. Standalone mode retains operator-maintained JavaScript rules; a
binary upgrade does not enable team authentication. Deno remains pinned at
2.9.8, so no new JavaScript-engine migration is required.

### Features and fixes

- **Team permissions:** verify identity through Stargate and account status
  through Warden; require explicit source ownership/read access. Reader
  credentials are read-only and individually revocable. Every private read is
  authorized, including cache hits and `304` responses. Logging in cannot
  re-enable a locally disabled account.
- **Source wizard:** preview and save public SSR sources without JavaScript,
  check revisions on edits, restore/delete/refresh sources and manage reader
  credentials. Selector and page budgets bound user input. `rssc doctor`
  diagnoses startup without modifying the authorization database.
- **Fetch policy:** enforce public SSR destinations in team mode, including DNS,
  redirect and cache-policy checks. Each generation shares a 64-request/64-MiB
  upstream budget. Keep internal targets, browser rules and Cookie/proxy
  integrations in a separate trusted standalone deployment.
- **Snapshots and scheduling:** retain complete successful feeds, with default
  freshness of 30 seconds and up to 3600 additional stale seconds, conditional
  HTTP responses and per-owner work limits. Manual refresh bypasses and replaces
  page caches; older concurrent fetches cannot overwrite newer successful
  content. Managed revisions have separate page caches, and preparation panics
  no longer leak admission permits.
- **Feed safety:** sanitize HTML from every rule using an allowlist. Remove CSS,
  scripts, active embeds and automatically loaded resources; replace images
  with alternative text. JSON summaries are plain text, preserving adjacent
  inline text and separation between block-level content.
- **Deployment:** require POST plus an explicit action header for management
  mutations, redact sensitive log details, run images as UID/GID 65532 and use
  private Deno worker caches. The guided Stargate example exposes only the
  gateway, separates operator access and generates private configuration, with
  static and live Nginx verification.

### Before upgrading

1. Back up rules, deployment settings and any existing team authorization store.
   Run the new `rssc doctor`, check mount permissions and verify readiness.
2. Snapshots are enabled by default. Set `RSS_SNAPSHOT_TTL=0` to disable output snapshots
   while retaining the document cache, or `RSS_SNAPSHOT_MAX_STALE=0` to reject stale responses.
   A rule's `DisableCache` still disables caching.
3. Review feeds that depend on images, custom CSS or embeds: their output changes,
   and there is no per-rule sanitizer bypass.
4. Migrate `/config/*` clients to POST with `X-RSS-Admin-Action: 1`; keep existing
   authentication and never inject the administrator token for all signed-in users.
5. Team mode needs identity, trusted proxy and source ACL configuration. Historical
   v0.4.0 ignores those settings and is not a safe team-mode rollback target.
   Only one process may write the authorization store; reconcile revoked
   credentials after restoring a backup.

See the [upgrade guide](https://github.com/soulteary/rss-can/blob/v0.5.0/docs/upgrading.md#upgrade-v050), [team access](https://github.com/soulteary/rss-can/blob/v0.5.0/docs/stargate-access.md),
[snapshot behavior](https://github.com/soulteary/rss-can/blob/v0.5.0/docs/feed-snapshots.md) and [feed content safety](https://github.com/soulteary/rss-can/blob/v0.5.0/docs/feed-content-safety.md).

## Distribution

Linux/macOS AMD64 and ARM64 archives include `rssc`, executable Deno 2.9.8,
rules and license notices. Extract the complete archive and verify its SHA-256
file. Linux archives require glibc; use the Debian container on musl/Alpine.
The Docker release tag is `soulteary/rss-can:v0.5.0` for Linux AMD64/ARM64.
Archives also include team documentation and deployment helper files. The guided
Stargate example builds a reviewed local source checkout; use a full checkout for
that workflow rather than treating the archive as a Docker build context.

```sh
docker pull soulteary/rss-can:v0.5.0
docker run --rm --user 65532:65532 -p 127.0.0.1:8080:8080 \
  -e RSS_REDIS=false -v "$(pwd)/rules:/rules:ro" soulteary/rss-can:v0.5.0
```

This starts standalone mode. Follow the [Stargate deployment guide](https://github.com/soulteary/rss-can/blob/v0.5.0/example/4.with-stargate/README.md)
for team access and the [secure deployment guide](https://github.com/soulteary/rss-can/blob/v0.5.0/docs/secure-deployment.md) for
resource limits, read-only filesystems and private service networks.
